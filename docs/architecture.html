1 · The five layers

Every command takes the same path from the touchscreen to the hardware. Nothing skips a layer, and only the last layer touches I²C/GPIO.

3 · The two flows that matter most

Start a cure — the normal path.

HomePageuser taps Start Cure
→
CureProcessPageper phase: commandPhase()
→
POST /api/cure/heat|cure-405|cool…validated 30–80 °C, UV ≥ 10 %
→
HardwareController → IOBridgereal board or simulation
→
SystemControllerpre-flight, then set_and_verify
→
heater / LEDs / fansUI sees it via /api/state 1 s later

Door opens during a cure — the safety path (unchanged by the refactor).

door sensor GPIO27read once per watchdog tick
→
UI: 10 s grace countdownCureProcessPage
→
StatusLeds watchdogopen ≥ 10 s with outputs on
→
IOBridge.door_abort()everything OFF, no fan run-on
→
/api/state doorAborted:trueUI alert 6016, back to Home
→
POST /api/door-abort/ackclears the fault

The four violet files are the ones the refactor introduced. Everything else already existed and was kept, cleaned or moved.

What is gone: 57 legacy / unused / prototype files (standalone drivers, Tk dashboards, the C++ driver, bench-analysis scripts, an unreachable material-editor page, unused components and assets). They were first parked under Not_Relevant/ in commit 32997e0 and then deleted in 8453e5c — recover any of them with git show 32997e0:Not_Relevant/….

The import graph is one-directional: app.py → {hardware_controller, storage, cloud_sync, db, io_bridge, updater}; io_bridge → io_controller/ only; the new modules import nothing project-internal. No cycles.

Deploy: on the Pi scure.service runs server/app.py and pi-kiosk.sh opens Chromium; on Windows win-start.bat runs the same API in simulation inside a desktop window.
